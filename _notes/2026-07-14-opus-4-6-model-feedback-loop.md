我的个人猜测是：Opus 4.6 标志着前沿模型开始大规模反哺模型训练。从 Opus 4.6 之后，大批模型的 Coding 和 Agent 能力迎来了巨大飞跃。Opus 4.5 到 4.6 固然是一次很大的进步，但其他追赶者的进步幅度更大。

一般来说，最前沿的开源模型与头部闭源模型之间，往往只相差三到六个月。但这只是前沿竞争者之间的距离，更多厂商看上去早已被甩开了巨大的差距，尤其是在真实工程可靠性上，跑分所显示的距离远远小于实际使用中的距离。

在 Opus 4.6 发布后的五个月里，我猜测各家厂商逐渐吸收、消化了它强大的 Agent Coding 能力，并将这些能力应用到自己的模型和产品中，最终实现了跨越。第一个跨过我心中那条生产力分界线的追赶者，是智谱的 GLM-5.2。单看跑分，GLM-5.2 的进步还不是后来这些模型中最大的，但它发布时带来的震撼相当强烈。

在我看来，Opus 4.5 可以算作一条生产力标准线。跨过这条线以后，我可以放心地让模型生成大段代码，不再默认它一定会犯低级错误，也不必从头到尾逐行检查。我的主要精力会从“修模型写出的代码”，转移到“在交付任务前，怎样把需求表达清楚”。

在 Opus 4.5 之前，没有哪个模型能让我对它生成的大段代码真正感到安心，包括合并 Codex 能力之前的 GPT-5.2。而 GLM-5.2 出现以后，智谱成为了全世界第三家跨过这条理想生产力线的厂商。我可以放心地把大段代码任务交给它，只需要操心如何准确表达需求，然后等着没有明显错误、可以直接使用的代码出现在电脑上。

而当时 Grok 唯一的作用就是生产黄图，但在这一轮 Coding 能力飞跃以后，最新的 Grok 4.5 也已经能够稳定写出不容易出错的代码。我甚至在 AGENTS.md 中允许 Codex 在控制台调用 Grok，把它作为轻型模型使用，这种变化放在几个月前几乎难以想象。

HY 和 LongCat 一度让我认为它们已经退出了前沿大模型竞争，但最新正式版本发布以后，它们的跑分出现了巨大进步，真实使用体验的提升也相当明显。它们目前还没有跨过我心中的生产力分界线，但至少重新回到了牌桌上，我也更期待它们接下来的更新。

如果用一条完全主观的生产力刻度衡量：2025 年中，模型的水平从 10 分进步到了 20 分；而在已经过去的 2026 年前七个月里，模型的水平从 20 分直接提高到了 60 分，仿佛被 Opus 4.6 带着整个行业一起飞快进步。

从 Opus 4.6 开始，前沿模型就不再只是一款产品，也可能变成整个行业下一轮训练的数据基础设施。Opus 4.6 也许就是这一轮大规模反哺的开端，我已经不敢想象 Mythos 和 GPT-6 级别的模型出现以后，又会把大模型的发展速度推到什么程度。
